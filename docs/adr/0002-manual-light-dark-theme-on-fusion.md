# 0002 — 明暗两档手动换肤，控件风格固定为 Fusion

状态：accepted（2026-10-07）

右上角工具栏加一个按钮，在浅色与暗夜之间一键切换，档位存进 `ui/theme_mode`（存名字，同
`preview_quality`：整数会跟着枚举顺序漂移）。`app.setStyle("Fusion")` 无条件生效，**浅色档也自带
一套取值**，照改造前的外观写死，不再依赖系统调色板。

颜色全部是数据，落在 `polcam/core/theme.py`：一个 `ThemeMode` 加两个 `ThemeTokens`，不碰 Qt，
于是"两个档声明了同样的角色""深色档的文字压得住深色底"这类断言能脱离 QApplication 检查。
把它们变成 `QPalette` 的是 `polcam/gui/app_theme.py`，那里还负责一件事：图标不复制第二套 svg，
而是加载时按当前 `ButtonText` 上色（`themed_icon`），缓存键带档位。

换肤的生效路径是 `MainWindow._set_theme`，它是唯一的入口：应用调色板 → 重画顶栏（背景、每个
图标的位图、换肤按钮自己）→ 重描两个分割条 → 重画图像工具栏那一排。

## 备选方案

- **跟随系统深浅（Qt 6.5+ 的 `colorScheme`）**：用户要的是"一键切换"，跟随系统给不了手动开关；
  而且看偏振图时会把"图像本身的颜色"和"界面的颜色"混在一起判断。
- **只换 `QPalette` 不换 style**：原生风格各有取色逻辑（Windows 读注册表，Linux 跟桌面主题），
  深色 palette 贴到原生按钮上会出现半深半浅的拼贴。Fusion 完整听 `QPalette` 的话，代价是浅色档
  也得自己给值。
- **深浅各存一套 svg**：六个图标 × 两个档，漏一个就是一排旧颜色；上色这条路一份资源就够。
- **做配色主题系统（用户自定义色）**：只有明暗两个真实需求，YAGNI。

## 后果

- 这条**推翻了"保持原生 Qt 外观、不引入配色主题"的旧方向**：观感仍然是原生的（浅色档就是照今天
  的取值写的），但明暗由我们自己的取值决定，不再由系统决定。
- 任何自带 QSS 颜色或位图图标的新控件，都必须在 `_set_theme` 的刷新路径里登记，否则换肤后会留下
  旧颜色 —— 真平台截图抓到过一次：顶栏背景与六个图标没跟着变，因为它们是在启动时按当时的调色板
  渲染成位图的。相应地 `Styles.apply_splitter_style` 不再是"构造时调一次"的函数。
- 禁用态必须显式给颜色：不给的话 Qt 沿用同组颜色，深色档下"禁用"和"可用"长得一样。
- 打包不需要新增资源：`PolCam.spec` 的 `datas` 已经整目录带上 `polcam/resources`。
- 取证口径：截图必须在真实平台上拍（`offscreen` 会把中文渲染成豆腐块），浅色与暗夜各一张，
  外加"重启后回到离开时的档位"。
