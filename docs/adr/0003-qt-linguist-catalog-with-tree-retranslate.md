# 0003 — 中英双语用 Qt Linguist 目录，切换时按目录整句重译

状态：accepted（2026-10-08）

代码里写的中文就是**源语言**，所以只有 `polcam_en` 一份目录：中文档不装 `QTranslator`
（装一份 zh.qm 只会多出一个会和代码脱节的副本），英文档装上 `polcam_en.qm`，Qt 在每次
`tr()` 求值时查表。档位存 `ui/language`，名字而不是整数。

`.ts`、生成的 `.qm` 与 `sources.json` 三者都提交进仓库，`tools/build_translations.py --check`
是它们的一致性门，拦三件事：有句子没译文；已提交的产物与重新生成的不一致；**设文字的调用里
塞了没包 `tr()` 的中文字面量**（含 f-string）。第三条是真正的护栏 —— 前两条只保证目录内部一致，
漏包一句的话目录再满，英文界面也会有一块留在中文。

切换语言要立刻生效。控件在构造期就把文字设进去了，`tr()` 是求值时才查表，所以换目录不会让
已上屏的文字自己变。这里用两条路覆盖：

1. `gui/i18n.py` 的 `retranslate_tree()` 按 `sources.json` 遍历控件树，把当前显示的文字**整句**
   还原成源文再按新语言取一次（源文和译文都作为键，所以两个方向都能还原）。下拉框的条目不是
   控件自己的 `text()`，单独按 index 重设。
2. 少数显示文字是拼出来的（`"0 项"`、`"相机状态：未连接"`、工具栏的 `"名字：说明"`），
   整句匹配不到目录，由控件自己的 `refresh_texts()` 重算。

由此得出一条要长期守住的规则：**给用户看的整句，必须是目录里的一个键**。所以引导页的项目符号
"· " 写在源文里面而不是拼在外面；参数标签把单位带进源文（`"曝光时间 (us):"`）而不是运行时拼。

## 备选方案

- **自造中英字典**：需求阶段就被否掉，明确要引 Qt Linguist 工具链。
- **改用 Designer `.ui` + `retranslateUi()`**：那是 Qt 对这个问题的官方答案，但界面是手写构造的，
  迁移比现在这两条路更贵。
- **切换后重启应用 / 重建主窗口**：用户要的是"立即重刷"；重建窗口还会打断在飞的采集与连接。
- **跟随系统 locale**：外部用户装完就是中文界面（源语言），要英文只能改系统区域设置。

## 后果

- 新增界面文字必须走 `self.tr()` / `QCoreApplication.translate(ctx, ...)`，**且字面量要直接写在
  调用里**：`tr = QCoreApplication.translate` 这种别名、`_ui_text(x)` 这种自定义函数名、
  `addItem(quality.label)` 这种"值在别处"的写法，lupdate 都扫不到。字典里的值要标
  `QT_TRANSLATE_NOOP(ctx, "...")`。
- 带变量的句子用 `%1` 占位再 `replace`，不许用 f-string（f-string 不是字面量）。
- 措辞属于界面层：`core/capability.py` 只留事实，句子搬到 `gui/capability_text.py`；
  `PreviewQuality.label` 不再直接上界面，档位名写在设置对话框的字面量里。
- 打包必须带上 `polcam/translations`（`PolCam.spec` 的 `datas`），漏了不会崩 —— `apply_language()`
  会退回中文并在日志里说一句。
- 英文比中文长两三成：标签要能换行，否则会被裁掉半句（引导页的正文就是这么发现的）。
- 日志正文、数据库字段与文件后缀、changelog 不进目录。
- 取证口径：`offscreen` 下"先建窗口再切语言"会暴露整句匹配不到的漏网文字，而"启动即英文"不会 ——
  所以测试按运行中切换来测，截图在真实平台上拍（中文渲染需要真字体）。
